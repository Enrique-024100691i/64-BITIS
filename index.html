Introducción

El presente informe detalla el diseño del Modelo Conceptual de Base de Datos para la empresa Intrasev Motors[cite: 284]. El objetivo es aplicar fundamentos teóricos para resolver la gestión de inventario y ventas de repuestos de alta gama en un entorno real[cite: 285, 287].

1. Contexto: ¿Qué es Intrasev Motors?

Ubicada en Cusco, se dedica a la comercialización de motores y repuestos premium (Audi, BMW, Mercedes-Benz)[cite: 290, 291]. La empresa busca organizar su flujo constante de información para vincular catálogo, ventas, clientes y empleados de forma exacta[cite: 293, 294].

2. Requerimientos del Negocio

  • REQ-01: Gestión de Inventario (categoría, marca compatible, stock)[cite: 301].
  • REQ-02: Registro de Clientes (DNI/RUC, Razón Social)[cite: 302].
  • REQ-03: Trazabilidad de Empleados por transacción[cite: 303].
  • REQ-04: Control detallado de ventas (productos, cantidades y subtotales)[cite: 304].
  • REQ-05: Reglas de negocio (no permitir montos negativos)[cite: 305].

5. Implementación en SQL Server

A continuación se presenta un extracto del código DDL para la creación de las tablas principales[cite: 388, 416, 425]:

-- Creación de Tabla Cliente
CREATE TABLE Cliente (
    ID_Cliente INT PRIMARY KEY IDENTITY(1,1),
    Razon_Social_Nombre VARCHAR(150) NOT NULL,
    DNI_RUC VARCHAR(20) NOT NULL UNIQUE,
    Telefono VARCHAR(15),
    Correo VARCHAR(100)
);

-- Creación de Tabla Venta
CREATE TABLE Venta (
    ID_Venta INT PRIMARY KEY IDENTITY(1,1),
    Fecha_Venta DATETIME DEFAULT GETDATE(),
    Total DECIMAL(10,2) NOT NULL,
    ID_Cliente INT NOT NULL,
    ID_Empleado INT NOT NULL,
    CONSTRAINT FK_Cliente_Venta FOREIGN KEY (ID_Cliente) REFERENCES Cliente(ID_Cliente)
);

Conclusión

El modelo centraliza eficientemente la información crítica de Intrasev Motors, eliminando redundancias y permitiendo una arquitectura escalable para la transformación digital de la empresa[cite: 505, 507].
